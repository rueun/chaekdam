# 토론 시스템 프롬프트 (하이브리드 모드)

> Claude API 의 시스템 메시지 구조 — 페르소나 + 책 메타데이터 + 운영 가드레일.
> 매 토론 시작 시 한 번 구성, 메시지 history 가 누적되어도 시스템 메시지는 동일 → **프롬프트 캐싱** 적용.

---

## 1. 시스템 메시지 구조

```
[블록 1: 페르소나 시스템 프롬프트]   ← personas.systemPrompt 그대로 주입

[블록 2: 책 메타데이터]              ← Book + Author 의 정보로 동적 생성

[블록 3: 운영 가드레일]              ← 책담 공통 규칙 (모든 페르소나 공통)
```

→ 블록 1·2·3 모두 시스템 메시지에 포함. **`cache_control: { type: "ephemeral" }`** 적용해 다음 turn 부터 입력 토큰 비용·시간 ↓.

---

## 2. 블록 2 — 책 메타데이터 템플릿

```
지금 사용자가 함께 이야기하고자 하는 책은 다음과 같습니다:

- 제목: {book.title}
- 저자: {author.name}{author.nationality ? ` (${author.nationality})` : ''}
- 장르: {book.genre}
- 간단 요약: {book.summary}
{book.authorStyle ? `- 저자 스타일: ${book.authorStyle}` : ''}

이 책의 인상 깊은 구절에 대해 사용자와 5~10턴 정도의 깊이 있는 대화를 진행하세요. 사용자의 감상·생각이 더 풍부해지도록 도와주세요.
```

→ `book.summary` 는 200자 이내 (DB 제약). 너무 길면 캐싱 효율 ↓.

---

## 3. 블록 3 — 운영 가드레일 (공통)

```
[운영 가드레일]

언어:
- 한국어로 응답합니다.

길이:
- 한 응답은 200~500자 내외. 깊이가 필요할 때만 길게.
- 사용자가 짧게 말하면 짧게 응답.

대화 흐름:
- 5~10턴 정도 자연스럽게 이어지도록.
- 사용자가 "토론 종료" 의사를 보이면 자연스럽게 마무리.
- 매 응답에 새 질문을 강요하지 않습니다 (대화의 호흡 존중).

내용 가드레일:
- 책의 핵심 결말·반전은 사용자가 먼저 언급하지 않으면 스포일러 금지.
- 사용자 노트 외의 책 텍스트를 길게 인용하지 않습니다 (저작권).
- 사용자 의견을 단정적으로 부정하지 않습니다.
- 의학·법률·금융 등 전문 조언이 필요한 영역은 "전문가 상담 권장" 안내.
- 개인 식별 정보·위치·연락처를 묻지 않습니다.

응답 형식:
- 마크다운 사용 가능 (강조·인용·목록).
- 코드 블록은 사용하지 않습니다.
- 외부 링크·구매 추천 금지.
```

## 4. 첫 사용자 메시지 (`Discussion.start` 시 자동 생성)

```
인상 깊은 구절을 가져왔어요:

> {note1.content}

{noteCount > 1 ? `> ${note2.content}` : ''}
{noteCount > 2 ? `> ${note3.content}` : ''}

이 부분이 마음에 남았어요. 함께 이야기해주세요.
```

→ 마크다운 인용(`>`)으로 노트 구분. AI 가 어떤 부분이 사용자 노트인지 명확히 인식.

## 5. 메시지 history 구조

Claude API 호출 시:

```typescript
{
  model: 'claude-sonnet-4-6', // 또는 latest
  max_tokens: 1024,
  system: [
    {
      type: 'text',
      text: persona.systemPrompt,
      cache_control: { type: 'ephemeral' },
    },
    {
      type: 'text',
      text: bookMetadataBlock,
      cache_control: { type: 'ephemeral' },
    },
    {
      type: 'text',
      text: guardrailBlock,
      cache_control: { type: 'ephemeral' },
    },
  ],
  messages: [
    { role: 'user', content: firstUserMessage }, // 노트들
    { role: 'assistant', content: aiFirstResponse },
    { role: 'user', content: userMessage1 },
    { role: 'assistant', content: aiResponse1 },
    // ...
    { role: 'user', content: latestUserMessage },
  ],
  stream: true,
}
```

## 6. 토큰·비용 추정

| 항목                        | 토큰 (대략) |
| --------------------------- | ----------- |
| 페르소나 시스템 프롬프트    | ~300        |
| 책 메타 블록                | ~150        |
| 운영 가드레일               | ~400        |
| **시스템 총합 (캐시 대상)** | **~850**    |
| 첫 사용자 메시지 (노트들)   | ~200~600    |
| 매 turn 사용자 메시지       | ~50~300     |
| 매 turn AI 응답             | ~200~500    |

→ 5~10 turn 기준 한 토론 약 5,000~15,000 토큰. 캐싱으로 입력 비용 ~50% 절감 예상.

---

## 7. 모델 선택

- **V1**: `claude-sonnet-4-6` (균형)
- **검토**: `claude-haiku-4-5` 로 비용 절감 (응답 깊이 비교 후 결정)
- **고급 페르소나** (POETIC, PHILOSOPHICAL): Sonnet 또는 Opus

---

## 8. 페일 / 폴백 전략

| 상황                          | 폴백                                                             |
| ----------------------------- | ---------------------------------------------------------------- |
| API 호출 실패                 | 1회 재시도 후 사용자에게 "잠시 후 다시 시도" 안내                |
| 응답이 가드레일 위반          | 재생성 1회 (다른 seed) 후 그래도 위반이면 안전 기본 응답         |
| 토큰 예산 초과 (history 누적) | 오래된 메시지 압축 또는 사용자에게 "토론 종료 후 새로 시작" 권장 |
| 응답 길이 max_tokens 초과     | 정상 동작 (잘림). UI 에 "더 보기" 표시                           |

---

## 9. 검증 (테스트)

- **단위**: 시스템 프롬프트 빌더 함수 (페르소나 + 책 메타 + 가드레일 결합) 입력별 출력 검증
- **통합**: Claude API 호출 시 캐시 히트율 (응답 메타 확인)
- **수동**: 대표 책 3권 × 페르소나 3개 = 9개 시뮬레이션 토론 → 톤·깊이·가드레일 위반 여부 점검 (2주차 종료 시점)
