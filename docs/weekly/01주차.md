## 1. 하네스 엔지니어링이란

> "프롬프트로 부탁하지 말고 시스템으로 강제하라."

### 핵심 5원칙

1. **모델보다 환경을 바꿔라** — 결과가 나쁘면 모델이 아니라 하네스 설계를 점검
2. **실패에서 시작하라** — 완벽한 사전 설계 X. 실패 시 구조적 방지 장치 추가
3. **적게 넣어라** — 규칙이 너무 많으면 오히려 성능 저하
4. **시스템으로 강제하라** — 프롬프트로 부탁하지 말고 훅 / 린터 / 테스트로 강제
5. **하네스도 진화한다** — 모델 발전에 맞춰 계속 갱신

### Spring 개발자 관점 비유

| 하네스 개념      | Spring 비유                              |
| ---------------- | ---------------------------------------- |
| Claude Code 환경 | Spring Boot 프로젝트 환경                |
| `CLAUDE.md`      | `application.yml` + 프로젝트 컨벤션 문서 |
| 자동 차단 훅     | pre-commit + Spotless + Checkstyle       |
| 서브 에이전트    | 정적 분석 도구 (SpotBugs / SonarQube)    |
| 슬래시 명령어    | IDE Run Configuration                    |

## 2. 글로벌 설정 (`~/.claude/`)

모든 프로젝트에 자동 적용되는 사용자 레벨 설정.

### 디렉토리 구조

```
~/.claude/
├── CLAUDE.md                   # 진입점 (~50줄, @import만)
├── settings.json               # 훅 등록·플러그인 활성화
├── rules/                      # 프레임워크 무관 규칙 (9개)
├── templates/                  # 프로젝트 부트스트랩 템플릿 (4개)
├── agents/                     # 서브 에이전트 (2개)
├── commands/                   # 슬래시 명령어 (3개)
└── hooks/                      # 자동 검증·차단 스크립트 (4개)
```

### 2-1. `rules/` — 자동 로드 규칙 (9개)

`CLAUDE.md`에서 `@import`로 명시한 파일이 매 세션 자동 로드. **폴더에 두는 것 ≠ 자동 로드**, `@import` 필수.

| 파일                 | 자동 로드            | 핵심 내용                                                         |
| -------------------- | -------------------- | ----------------------------------------------------------------- |
| `language.md`        | ✅ 항상              | 한국어 응답 / 영어 로그·에러                                      |
| `workflow.md`        | ✅ 항상              | Mock 금지, 디버그 print 금지, 문제 해결 우선순위                  |
| `code-principles.md` | ✅ 항상              | OOP·SOLID·What 기반 네이밍·도메인 객체 불변성                     |
| `git-conventions.md` | ✅ 항상              | 한국어 Conventional Commits·PR 형식                               |
| `tooling.md`         | ✅ 항상              | Lefthook·oxlint·Prettier·환경 변수 정책                           |
| `architecture.md`    | ✅ 항상              | Clean Architecture (계층별 책임·의존성 방향)                      |
| `ddd.md`             | ✅ 항상              | DDD 핵심 (Aggregate·Entity·VO·Port&Adapter)                       |
| `design-patterns.md` | ✅ 항상              | Strategy·Factory·Repository·Builder·Specification                 |
| `frontend.md`        | 🔶 프로젝트별 import | React/TS 패턴 (백엔드 단독 프로젝트엔 잡음이라 자동 import 안 함) |

#### 각 파일이 정의하는 것

- **`language.md`** — 응답·주석·커밋 메시지는 한국어, 에러·로그는 영어 (운영 환경 호환성)
- **`workflow.md`** — "Mock으로 핵심 도메인 가짜 처리 금지", "console.log·System.out.println 금지" 같은 절대 금지 사항. 문제 해결 우선순위 (실제 동작 → 기존 패턴 → 테스트 가능)
- **`code-principles.md`** — `register()` vs `saveToDatabase()` 같은 What 기반 네이밍, 도메인 객체 불변성 (private 생성자 + 정적 팩토리)
- **`git-conventions.md`** — `feat(order): 주문 부분 취소 기능 추가` 같은 한국어 Conventional Commits, PR 본문 형식
- **`tooling.md`** — Lefthook·oxlint·Prettier 표준 설정, `.env` 우선순위
- **`architecture.md`** — Domain → Service → Infra 의존성 방향, 계층별 책임
- **`ddd.md`** — Aggregate 경계, Port & Adapter 매핑 (`OrderRepository` ↔ `PostgresOrderRepository`)
- **`design-patterns.md`** — Strategy·Factory·Repository·Builder·Specification 도입 기준
- **`frontend.md`** — react-hook-form + zod, TanStack Query, react-error-boundary, nuqs, overlay-kit, 라우트 상수, 컴포넌트 응집

#### 왜 분리했나

- 글로벌 `CLAUDE.md` 는 진입점으로 짧게 (~50줄, 100줄 이하 권장)
- 카테고리별 `rules/*.md` 로 분리하면 관심사 분리 + 부분 import 가능
- `frontend.md` 만 조건부 import — 백엔드 단독 프로젝트에선 React 패턴 불필요

### 2-2. `templates/` — 프로젝트 부트스트랩 (4개)

새 프로젝트 시작 시 골격을 빠르게 복사하기 위한 템플릿.

| 템플릿             | 대상                                              | 포함 파일                               |
| ------------------ | ------------------------------------------------- | --------------------------------------- |
| `nestjs/`          | NestJS + TypeScript                               | `CLAUDE.md`, `rules/{stack,testing}.md` |
| `spring-java/`     | Spring Boot + Java                                | `CLAUDE.md`, `rules/{stack,testing}.md` |
| `spring-kotlin/`   | Spring Boot + Kotlin                              | `CLAUDE.md`, `rules/{stack,testing}.md` |
| `nextjs-supabase/` | Next.js + Supabase + Claude API ← **책담이 사용** | `CLAUDE.md`, `rules/{stack,testing}.md` |

#### 사용 방법

```bash
# 새 프로젝트 시작 시
mkdir my-project && cd my-project
cp -r ~/.claude/templates/<스택>/. .claude/

# 예: NestJS 백엔드 시작
cp -r ~/.claude/templates/nestjs/. .claude/

# 예: Next.js + Supabase (책담)
cp -r ~/.claude/templates/nextjs-supabase/. .claude/
```

각 템플릿은 **언어별 표현(`final`, `val`, `readonly` 등)·프레임워크 컨벤션·테스트 도구**가 구체화됨. 글로벌 `~/.claude/rules/` 는 프레임워크 무관 원칙만, 템플릿은 그것을 언어 / 프레임워크로 풀어 씀.

### 2-3. `agents/` — 서브 에이전트 (2개)

특정 검사를 전담하는 AI 에이전트. Claude가 메인 작업을 하다가 필요할 때 호출.

| 에이전트                | 역할                                              |
| ----------------------- | ------------------------------------------------- |
| `architecture-guard`    | 클린 아키텍처 의존성 위반 검사                    |
| `domain-model-reviewer` | 도메인 모델 원칙 검증 (불변성·팩토리·What 네이밍) |

#### `architecture-guard` 가 검사하는 항목

- **도메인 계층 독립성** — `domain/` 파일이 `org.springframework.*`, `@nestjs/*`, `@supabase/*`, `next/*`, `react` 등을 import 하면 위반
- **의존성 방향** — Service 가 `JpaXxxRepository`, `SupabaseXxxRepository` 같은 구체 구현을 직접 import 하면 위반 (Port 인터페이스만 의존해야 함)
- **비즈니스 로직 누수** — Controller·Server Action 에 비즈니스 분기 (`if/else` 도메인 상태 판단) 가 있으면 위반
- **DTO 누수** — `*Request`, `*Dto` 가 Domain·Application 계층까지 전파되면 위반

#### `domain-model-reviewer` 가 검사하는 항목

- **불변성** — `final` / `val` / `readonly` 누락, setter 메소드 존재, 상태 변경 시 새 객체 미반환
- **생성자** — public 생성자 (private + 정적 팩토리여야 함)
- **What 기반 네이밍** — `saveToDatabase`, `fetchFromCache`, `callExternalAPI` 같은 구현 노출 메소드명 검출
- **정보 전문가 패턴** — Service 에서 `if (order.getStatus() == ...)` 후 분기 (도메인 객체에 메소드를 만들어 위임해야 함)
- **프레임워크 독립성** — 도메인 클래스에 `@Entity`, `@Service`, `@Injectable` 등 어노테이션 부착 검출

#### 호출 방법

- **자연어로**: "방금 작성한 코드 architecture-guard로 검사해줘"
- **슬래시 명령어로** (권장): `/arch-check`, `/domain-check`, `/arch-review`

### 2-4. `commands/` — 슬래시 명령어 (3개)

자연어 대신 결정적 트리거. 자연어는 모델이 의도 못 잡을 수 있지만 슬래시는 100% 동작.

| 명령어                 | 동작                                    | 사용 시점                                |
| ---------------------- | --------------------------------------- | ---------------------------------------- |
| `/arch-check [경로]`   | architecture-guard 호출                 | Domain·Service·Infra 코드 작성 / 수정 후 |
| `/domain-check [경로]` | domain-model-reviewer 호출              | 도메인 엔티티·VO 작성 / 수정 후          |
| `/arch-review [경로]`  | 두 에이전트 **병렬** 실행 + 종합 리포트 | PR 직전·도메인 큰 변경 후                |

#### 사용 예

```text
/arch-review                              # 최근 변경된 파일 (git status) 자동 검사
/arch-review lib/domain/                  # 특정 경로만 검사
/domain-check lib/domain/order/order.ts   # 단일 파일 검사
```

#### 출력 형식 (예)

```
🚨 클린 아키텍처 위반 2건 발견

1. lib/domain/order/order.ts:5
   계층: Domain
   문제: Domain 계층이 @supabase/supabase-js 를 import
   해결 방향: Port 분리 후 Adapter 는 lib/infrastructure/ 에서 구현

2. ...
```

### 2-5. `hooks/` — 자동 검증·차단 (4개)

`settings.json` 의 PreToolUse · PostToolUse · Stop 이벤트에 등록되어 코드 작성 / 저장 / 응답 종료 시점에 자동 실행. **부탁이 아니라 차단**.

| 훅                          | 이벤트                   | 동작                                         |
| --------------------------- | ------------------------ | -------------------------------------------- |
| `check-secrets.py`          | PreToolUse (Write·Edit)  | 시크릿·API 키·토큰 12종 패턴 → **저장 차단** |
| `check-debug-prints.py`     | PreToolUse (Write·Edit)  | `console.log`, `System.out.println` → 차단   |
| `post-edit-lint.sh`         | PostToolUse (Write·Edit) | 파일 확장자별 자동 린트 (TS·JS·KT·PY)        |
| `domain-change-reminder.sh` | Stop (응답 종료)         | `domain/` 변경 시 `/arch-review` 안내 주입   |

#### `check-secrets.py` 감지 패턴 12종

- Anthropic API Key (`sk-ant-api...`, `sk-ant-admin...`)
- OpenAI API Key (project / legacy)
- AWS Access Key ID (`AKIA[A-Z0-9]{16}`)
- GitHub Personal Access Token (`ghp_...`, `gho_...`, `github_pat_...`)
- Slack Token (`xoxb-`, `xoxp-` 등)
- Stripe Live Key (`sk_live_`, `pk_live_`)
- Google API Key (`AIza...`)
- JWT Token (`eyJ...eyJ...`)
- PEM Private Key (PEM 헤더 / 푸터 패턴)

→ `.env`, `.env.local`, `secrets/`, `credentials.*` 경로는 검사 제외 (시크릿의 정당한 보관처).

#### `domain-change-reminder.sh` 동작

- `git status` 에서 `domain/` 또는 `application/` 경로 변경 감지
- 변경 있으면 응답 종료 시 자동 메시지 주입:
  ```
  📝 도메인 코드 변경 감지
  검사 명령:
    /arch-check    - 클린 아키텍처 의존성 위반
    /domain-check  - 도메인 모델 원칙
    /arch-review   - 두 검사 병렬 실행 + 종합 리포트
  ```
- 사용자가 잊지 않고 검사하도록 시스템적 push.

## 4. 기술 스택

### 핵심 스택

| 영역          | 기술                                           | Spring 비유                                    |
| ------------- | ---------------------------------------------- | ---------------------------------------------- |
| 프레임워크    | **Next.js 15.5** (App Router)                  | Spring Boot 3.x                                |
| 언어          | **TypeScript 5.9** (strict)                    | Java/Kotlin (strict null check)                |
| 스타일링      | **Tailwind CSS 4**                             | 디자인 시스템 + 템플릿                         |
| BaaS          | **Supabase** (Postgres + Auth + Storage + RLS) | Spring Security + JPA + S3 + Spring Cache 통합 |
| AI            | **Claude API** (multimodal vision)             | LLM SDK                                        |
| 배포          | **Vercel**                                     | AWS Lambda + ECR + Route 53                    |
| 테스트        | **Vitest** + **Playwright**                    | JUnit + Selenium                               |
| Node          | **24.13.0 LTS**                                | JDK 21                                         |
| 패키지 매니저 | **pnpm 10.33** (Corepack)                      | Maven / Gradle                                 |

### "백엔드는 어디 있나?"

전통적 Spring 백엔드는 **별도 서버**지만, Next.js + Supabase는 **분산**되어 있다.

| 책임             | 위치                                                 | Spring 비유                     |
| ---------------- | ---------------------------------------------------- | ------------------------------- |
| 비즈니스 로직    | Next.js Server Actions (`app/**/actions.ts`)         | `@Service` 메소드               |
| 외부 API/Webhook | Next.js Route Handlers (`app/api/**/route.ts`)       | `@RestController`               |
| 권한 검증        | Supabase RLS (SQL) + 도메인 Specification            | Spring Security `@PreAuthorize` |
| 인증             | Supabase Auth                                        | Spring Security                 |
| DB 접근          | Supabase 클라이언트 (`lib/infrastructure/supabase/`) | Spring Data JPA                 |
| AI 호출          | Server Action 내부 (Anthropic SDK)                   | 외부 API 클라이언트             |

→ 백엔드 코드와 책임은 **분명히 존재**, 다만 별도 서버로 분리되지 않은 상태.

## 6. 사용 방식 (How to use)

만든 자산을 실전에서 어떻게 활용하는지.

### 6-1. 새 프로젝트 시작 시

```bash
# 1. 디렉토리 + git 초기화
mkdir my-new-project && cd my-new-project
git init

# 2. 글로벌 템플릿 복사 (NestJS / Spring / Next.js+Supabase 중 선택)
cp -r ~/.claude/templates/<스택>/. .claude/

# 3. 프로젝트 CLAUDE.md 가 글로벌 + 프로젝트 한정 규칙을 import 함
#    → 이후 모든 Claude 세션에 자동 적용
```

### 6-2. 코드 작성 / 검증 흐름

```text
1. 코드 작성
   ↓
2. PreToolUse 훅 자동 실행
   ├─ 시크릿·API 키 포함되면 → 저장 차단
   └─ console.log·System.out.println 포함되면 → 저장 차단
   ↓
3. PostToolUse 훅 자동 실행
   └─ 확장자별 자동 린트 (TS·JS·KT·PY)
   ↓
4. 응답 종료 시 Stop 훅
   └─ domain/ 변경 감지하면 다음 응답에 /arch-review 안내 주입
   ↓
5. 도메인·서비스·인프라 코드 변경 시
   └─ /arch-review (또는 /arch-check, /domain-check) 실행
   ↓
6. git commit
   └─ Lefthook pre-commit:
      ├─ oxlint --fix (자동 수정)
      ├─ eslint --fix (typed linting 포함)
      └─ prettier --write
      → 자동 재스테이징 후 커밋 진행
```

### 6-3. 글로벌 자산 백업·복원 (다른 머신)

```bash
# 한 번만 (현재 머신에서)
cd ~/.claude
gh repo create claude-config --private --source=. --push

# 다른 머신·새 PC 에서 복원
git clone git@github.com:<user>/claude-config.git ~/.claude
```

→ rules / templates / agents / commands / hooks / settings.json 모두 즉시 복원.

### 6-4. 글로벌 vs 프로젝트 작업 분담 기준

| 작업                                     | 위치        | 이유                    |
| ---------------------------------------- | ----------- | ----------------------- |
| 한국어 / 영어 정책                       | 🌍 글로벌   | 모든 프로젝트 공통      |
| OOP·SOLID 원칙                           | 🌍 글로벌   | 프레임워크 무관         |
| Clean Architecture 의존성 방향           | 🌍 글로벌   | 프레임워크 무관         |
| 디버그 print·시크릿 차단                 | 🌍 글로벌   | 모든 코드 보호          |
| Lefthook·oxlint·Prettier 표준 설정       | 🌍 글로벌   | 모든 프로젝트 동일 도구 |
| `final` vs `val` vs `readonly` 표현      | 📦 프로젝트 | 언어별 다름             |
| Spring `@Transactional` / NestJS DI 토큰 | 📦 프로젝트 | 프레임워크 한정         |
| Next.js Server Action 패턴               | 📦 프로젝트 | 프레임워크 한정         |
| Tailwind 디자인 토큰                     | 📦 프로젝트 | 프로젝트 한정           |
| 환경 변수 키 목록                        | 📦 프로젝트 | 프로젝트 한정           |

→ **변경 영향 범위로 결정**: 모든 프로젝트에 동일 적용 → 글로벌, 특정 프로젝트만 → 그 프로젝트 `.claude/`.

### 6-5. 자산이 동작하지 않는 경우 점검

| 증상                                | 점검 지점                                                |
| ----------------------------------- | -------------------------------------------------------- |
| 글로벌 규칙이 적용 안 됨            | `~/.claude/CLAUDE.md` 의 `@import` 명시 확인             |
| 프로젝트 규칙이 적용 안 됨          | `<project>/CLAUDE.md` 의 `@.claude/rules/X.md` 확인      |
| `/arch-check` 같은 슬래시 명령 없음 | `~/.claude/commands/*.md` 존재 여부 + Claude Code 재시작 |
| 훅이 차단 안 함                     | `~/.claude/settings.json` 의 hooks 등록 확인             |
| Lefthook pre-commit 안 돌음         | `pnpm exec lefthook install` 다시 실행                   |
