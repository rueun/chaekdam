## 1. 하네스 엔지니어링이란

> "프롬프트로 부탁하지 말고 시스템으로 강제하라."

### 핵심 5원칙

1. **모델보다 환경을 바꿔라** — 결과가 나쁘면 모델이 아니라 하네스 설계를 점검
2. **실패에서 시작하라** — 완벽한 사전 설계 X. 실패 시 구조적 방지 장치 추가
3. **적게 넣어라** — 규칙이 너무 많으면 오히려 성능 저하
4. **시스템으로 강제하라** — 프롬프트로 부탁하지 말고 훅 / 린터 / 테스트로 강제
5. **하네스도 진화한다** — 모델 발전에 맞춰 계속 갱신

### Spring 개발자 관점 비유

| 하네스 개념      | Spring 비유                              |
| ---------------- | ---------------------------------------- |
| Claude Code 환경 | Spring Boot 프로젝트 환경                |
| `CLAUDE.md`      | `application.yml` + 프로젝트 컨벤션 문서 |
| 자동 차단 훅     | pre-commit + Spotless + Checkstyle       |
| 서브 에이전트    | 정적 분석 도구 (SpotBugs / SonarQube)    |
| 슬래시 명령어    | IDE Run Configuration                    |

## 2. 글로벌 설정 (`~/.claude/`)

모든 프로젝트에 자동 적용되는 사용자 레벨 설정.

### 디렉토리 구조

```
~/.claude/
├── CLAUDE.md                   # 진입점 (~50줄, @import만)
├── settings.json               # 훅 등록·플러그인 활성화
├── rules/                      # 프레임워크 무관 규칙
├── templates/                  # 프로젝트 부트스트랩 템플릿
├── agents/                     # 서브 에이전트
├── commands/                   # 슬래시 명령어
└── hooks/                      # 자동 검증·차단 스크립트
```

### 2-1. `rules/` — 자동 로드 규칙 (9개)

`CLAUDE.md`에서 `@import`로 명시한 파일이 매 세션 자동 로드.

| 파일                 | 역할                                               |
| -------------------- | -------------------------------------------------- |
| `language.md`        | 한국어 응답 / 영어 로그·에러 정책                  |
| `workflow.md`        | Mock 금지 / 디버그 print 금지 / 문제 해결 우선순위 |
| `code-principles.md` | OOP·SOLID·What 기반 네이밍·도메인 객체 불변성      |
| `git-conventions.md` | 한국어 Conventional Commits·PR 형식                |
| `tooling.md`         | Lefthook·oxlint·oxfmt·환경 변수 정책               |
| `architecture.md`    | Clean Architecture (계층별 책임·의존성 방향)       |
| `ddd.md`             | DDD 핵심 (Aggregate·Entity·VO·Port&Adapter)        |
| `design-patterns.md` | Strategy·Factory·Repository·Builder·Specification  |
| `frontend.md`        | React/TS 패턴 (조건부 import — 프론트 프로젝트만)  |

### 2-2. `templates/` — 프로젝트 부트스트랩 (4개)

새 프로젝트 시작 시 `cp -r ~/.claude/templates/<stack>/. <project>/.claude/` 로 복사.

| 템플릿             | 대상                                              |
| ------------------ | ------------------------------------------------- |
| `nestjs/`          | NestJS + TypeScript                               |
| `spring-java/`     | Spring Boot + Java                                |
| `spring-kotlin/`   | Spring Boot + Kotlin                              |
| `nextjs-supabase/` | Next.js + Supabase + Claude API ← **책담이 사용** |

### 2-3. `agents/` — 서브 에이전트 (2개)

특정 검사를 전담하는 AI 에이전트.

| 에이전트                | 역할                                              |
| ----------------------- | ------------------------------------------------- |
| `architecture-guard`    | 클린 아키텍처 의존성 위반 검사                    |
| `domain-model-reviewer` | 도메인 모델 원칙 검증 (불변성·팩토리·What 네이밍) |

### 2-4. `commands/` — 슬래시 명령어 (3개)

자연어 대신 결정적 트리거.

| 명령어                 | 동작                                    |
| ---------------------- | --------------------------------------- |
| `/arch-check [경로]`   | architecture-guard 호출                 |
| `/domain-check [경로]` | domain-model-reviewer 호출              |
| `/arch-review [경로]`  | 두 에이전트 **병렬** 실행 + 종합 리포트 |

### 2-5. `hooks/` — 자동 검증·차단 (4개)

`settings.json`의 PreToolUse · PostToolUse · Stop 이벤트에 등록.

| 훅                          | 이벤트                   | 동작                                           |
| --------------------------- | ------------------------ | ---------------------------------------------- |
| `check-secrets.py`          | PreToolUse (Write·Edit)  | API 키·토큰·JWT 12종 패턴 감지 → **저장 차단** |
| `check-debug-prints.py`     | PreToolUse (Write·Edit)  | `console.log`, `System.out.println` → 차단     |
| `post-edit-lint.sh`         | PostToolUse (Write·Edit) | 파일 확장자별 자동 린트 (TS·JS·KT·PY)          |
| `domain-change-reminder.sh` | Stop                     | `domain/` 변경 시 `/arch-review` 안내          |

### 2-6. 글로벌 `~/.claude/` git 관리

- `.gitignore` — cache·sessions·plugins 제외
- 추적 대상: `rules/`, `templates/`, `agents/`, `commands/`, `hooks/`, `CLAUDE.md`, `settings.json`
- 35개 파일 추적, 초기 커밋 완료
- 다른 머신 / 새 PC 에서 `git clone`으로 즉시 복원 가능

## 4. 기술 스택

### 핵심 스택

| 영역          | 기술                                              | Spring 비유                                    |
| ------------- | ------------------------------------------------- | ---------------------------------------------- |
| 프레임워크    | **Next.js 15.5** (App Router)                     | Spring Boot 3.x                                |
| 언어          | **TypeScript 5.9** (strict)                       | Java/Kotlin (strict null check)                |
| 스타일링      | **Tailwind CSS 4**                                | 디자인 시스템 + 템플릿                         |
| BaaS          | **Supabase** (Postgres + Auth + Storage + RLS)    | Spring Security + JPA + S3 + Spring Cache 통합 |
| AI            | **Claude API** (Anthropic SDK, multimodal vision) | LLM SDK                                        |
| 배포          | **Vercel**                                        | AWS Lambda + ECR + Route 53                    |
| 테스트        | **Vitest** + **Playwright**                       | JUnit + Selenium                               |
| 패키지 매니저 | **pnpm 10.33**                                    | Maven / Gradle                                 |

### "백엔드는 어디 있나?"

전통적 Spring 백엔드는 **별도 서버**지만, Next.js + Supabase는 **분산**되어 있다.

| 책임               | 위치                                               | Spring 비유                     |
| ------------------ | -------------------------------------------------- | ------------------------------- |
| 비즈니스 로직      | Next.js Server Actions (`app/**/actions.ts`)       | `@Service` 메소드               |
| 외부 API / Webhook | Next.js Route Handlers (`app/api/**/route.ts`)     | `@RestController`               |
| 권한 검증          | Supabase RLS (SQL) + 도메인 Specification          | Spring Security `@PreAuthorize` |
| 인증               | Supabase Auth                                      | Spring Security                 |
| DB 접근            | Supabase 클라이언트 (lib/infrastructure/supabase/) | Spring Data JPA                 |
| AI 호출            | Server Action 내부 (Anthropic SDK)                 | 외부 API 클라이언트             |

→ 백엔드 코드와 책임은 **분명히 존재**, 다만 별도 서버로 분리되지 않은 상태.

## 6. 학습 포인트

### 깊이 이해한 것

1. **CLAUDE.md `@import` 동작 방식** — 폴더에 둔다 ≠ 자동 로드. CLAUDE.md에서 명시되어야 함
2. **글로벌 vs 프로젝트 분리** — 프레임워크 무관 (글로벌) vs 스택 한정 (프로젝트)
3. **Clean Arch + FSD 절충안** — 도메인은 수평 분리(Clean), UI만 수직 분리(FSD 일부)
4. **백엔드의 위치** — Next.js + Supabase에서도 백엔드 책임은 분명히 존재, 단지 분산됨
5. **하네스 = 시스템 강제** — "잘 짜줘" 부탁이 아니라 "못 짜면 저장 안 됨"

### 새로 배운 도구·라이브러리 (백엔드 개발자 시각)

- **Lefthook / oxlint / oxfmt** — Rust 네이티브 도구의 속도 (Java tool 대비 50~100배)
- **TanStack Query** — Spring Cache 같은 클라이언트 캐시
- **zod** — Bean Validation 같은 스키마, 타입까지 자동 추론
- **Supabase RLS** — DB 자체에서 권한 검증 (Spring Security를 SQL로 옮긴 것)
- **Claude API multimodal** — 사진 → Claude로 직접 전달 → OCR 별도 구현 불필요

### 결정 기준 정립

- **"실패에서 시작"** — 처음부터 완벽 X, 빈틈 발견 후 구조적 방어 추가
- **"적게 넣어라"** — 규칙 5개가 50개보다 효과적
- **"언제든 백엔드 분리 가능한 구조"** — 도메인 코드 격리 (lib/domain/ 외부 의존 0)
